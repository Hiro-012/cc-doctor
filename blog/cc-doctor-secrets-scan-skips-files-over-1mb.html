cc-doctor's secret scan silently skips any tracked file over 1MB — no pattern check runs on it at all

By HiroCheck · Published 2026-09-24

Every earlier gap documented on this blog for cc-doctor's secret scan is about what happens once a file is read: a pattern the five named checks don't cover, or a value shape the generic fallback's quote requirement rejects. This one sits a step earlier. It's a size gate that decides whether a file is read at all — and once a tracked file crosses it, none of those content checks, correct or not, ever get a chance to run.

The gate

secrets-scan.js caps how large a file it will inspect:

const MAX_FILE_BYTES = 1_000_000; // skip huge files, they're almost never source with secrets
...
if (!stat.isFile() || stat.size > MAX_FILE_BYTES) continue;

That continue runs before readFile is ever called on the file — before either SECRET_PATTERNS (the five named provider formats) or GENERIC_SECRET_PATTERN (the catch-all fallback covered in an earlier article on this blog) sees a single byte of it. The comment's premise — that a file over ~1MB is "almost never source with secrets" — is true of hand-written source, but not of every git-tracked file. Vendored or bundled JavaScript, a webpack/rollup output committed for a static demo or GitHub Pages site, or a checked-in data dump can all legitimately exceed 1MB, and a build-time environment variable inlined via a DefinePlugin-style substitution ends up baked into exactly that kind of file.

Reproduced against the real CLI

A git repo with one tracked file just over the limit, containing an unambiguous, correctly-formatted secret that the named AWS pattern would otherwise catch instantly:

$ python3 -c "
import random, string
random.seed(1)
pad = ''.join(random.choice(string.ascii_letters) for _ in range(1_050_000))
open('vendor.bundle.js', 'w').write(pad + '\n' + 'const cfg={awsKey:\"AKIAABCDEFGHIJKLMNOP\"};\n')
"
$ wc -c vendor.bundle.js
1050044 vendor.bundle.js
$ git add vendor.bundle.js && git commit -q -m "add bundle"
$ npx cc-doctor .
[INFO] [info] claude-md: No CLAUDE.md found. Optional, but it lets Claude
Code pick up project-specific conventions automatically. (CLAUDE.md)

cc-doctor: 0 error(s), 0 warning(s), 1 info.
$ echo $?
0

Zero findings. The AWS key is a plain, unobfuscated match for SECRET_PATTERNS's own regex — it's simply never tested, because the file is 44KB over MAX_FILE_BYTES.

Isolating size as the actual cause

Trimming the same file's padding so the identical key now sits in a file under the 1MB limit, with nothing else changed, flips the result:

$ python3 -c "
import random, string
random.seed(1)
pad = ''.join(random.choice(string.ascii_letters) for _ in range(900_000))
open('vendor.bundle.js', 'w').write(pad + '\n' + 'const cfg={awsKey:\"AKIAABCDEFGHIJKLMNOP\"};\n')
"
$ wc -c vendor.bundle.js
900044 vendor.bundle.js
$ git add vendor.bundle.js && git commit -q -m "trim bundle under limit"
$ npx cc-doctor .
[ERROR] [error] secrets-scan: Possible AWS Access Key ID committed in
vendor.bundle.js. If real, rotate it immediately and remove it from git
history. (vendor.bundle.js)
[INFO]  [info]  claude-md: No CLAUDE.md found. ...

cc-doctor: 1 error(s), 0 warning(s), 1 info.
$ echo $?
1

Same key, same filename, same tool, run seconds apart. The only difference between a silent pass and a correctly flagged AWS key is 150KB of surrounding padding — content that has nothing to do with whether the secret itself gets detected once the file is actually read.

What cc-doctor checks

cc-doctor is a free CLI that scans a repo's git-tracked files for hardcoded secrets, plus Claude Code-specific misconfigurations: an unscoped Bash(*) permission grant, a committed settings.local.json, hooks pointing at scripts that no longer exist, and hardcoded credentials in .mcp.json. It runs entirely against the local filesystem and git index — no network access, no API key required.

npx cc-doctor            # scan the current directory
npx cc-doctor path/to/repo

Measured against cc-doctor's 49-fixture accuracy corpus, the tool's recall is 100% (29/29 known-bad fixtures) with a 0% false-positive rate (0/20 known-clean fixtures) — full methodology in the project README. Every fixture in that corpus is well under 1MB, so this gap doesn't exercise the size gate and doesn't move either number. It's a coverage hole the corpus doesn't yet test for, not a regression. Nothing in this article changes cc-doctor's code; it documents the exact condition under which the scan stays silent, with the reproduction steps above to verify it independently.
