Deleting the line doesn't rotate the key — what "remove it from git history" actually means

By HiroCheck · Published 2026-08-19

cc-doctor's secret scan works by listing every file git currently tracks (git ls-files) and reading each one's present content, checking it against a set of known secret shapes — an AWS access key ID (AKIA...), a GitHub personal access token (ghp_...), an Anthropic/OpenAI-style API key (sk-...), a Slack token, a PEM private-key block — plus a generic key: "value" pattern for anything assigned to a field named api_key, secret, password, or token. That last pattern is deliberately wide, so it filters out the things that would otherwise flood every scan with noise: placeholder values like your-api-key-here or <redacted>, divider strings of repeated punctuation, and masks where every character is the same letter (a common way to sanitize a committed example without deleting it entirely).

All of that happens against the working tree as it exists right now. Nothing in the check opens a previous commit.

The gap that leaves open

If a secret was committed and later removed — the line deleted, the file rewritten, a fresh commit made — a rescan of the current tree finds nothing, because the current tree is clean. The secret hasn't gone anywhere, though. It's still sitting in whatever commit first introduced it, retrievable with an ordinary git log -p -- <path> or git show <old-sha>:<path>, by anyone who already has a clone of the repository — which, the moment a commit is pushed to a shared remote, is no longer just you. "I deleted it in the next commit" and "it's gone" are two different claims, and only cc-doctor's current-tree scan can verify the first one.

This isn't a blind spot cc-doctor hides — it's built into the wording of the warning itself. The message the tool prints for every match doesn't just say rotate it; it says "rotate it immediately and remove it from git history" — two actions, because fixing the file and cleaning the history are two different jobs, and the scanner can only ever confirm the first one is done.

Why rotate has to come first

Rewriting history to strip a secret out — with git filter-repo, the tool Git's own documentation for filter-branch now points people toward as the faster, safer replacement, or with the community-maintained BFG Repo-Cleaner, which GitHub's own support docs list as the other supported option — rewrites every commit SHA downstream of the change and requires a force-push, which is why GitHub recommends closing or merging any open pull requests first: their diffs point at commits that are about to stop existing. Even done correctly, though, scrubbing history only controls your copy of the repository going forward. It can't undo the fact that the secret was already live in a public (or shared) commit for however long it took to notice — already fetchable by anyone who cloned or forked in that window, already indexable by anything that scrapes public repos. That's the reason the credential itself has to be rotated regardless of whether the history rewrite happens at all; the rewrite is cleanup, not the fix.

A narrower related gap: quoted values only

The generic key: "value" pattern requires the value to sit inside quotes, which is how it tells a real assignment (password: "hunter27!") apart from a sentence that merely mentions the word ("reset your password before deploying"). The tradeoff is that an unquoted assignment in a shell-style file — API_KEY=sk-liveExampleValue123456 in a .env with no quotes around the value — falls outside that specific pattern. The five named patterns (AWS, GitHub PAT, OpenAI/Anthropic-style, Slack, private-key block) still match regardless of quoting, since they key off the value's own shape rather than its syntax context; it is the catch-all pattern specifically that depends on the quotes being there.

What cc-doctor checks

cc-doctor is a free CLI that scans a repo's git-tracked files for the patterns above, plus its other checks for Claude Code config (hardcoded secrets in .mcp.json, an unscoped Bash(*) permission grant, a committed settings.local.json, hooks pointing at scripts that no longer exist). It runs entirely against the local filesystem and git index — no network access, no API key required.

npx cc-doctor            # scan the current directory
npx cc-doctor path/to/repo

Measured against cc-doctor's 49-fixture accuracy corpus, the tool's recall is 100% (29/29 known-bad fixtures) with a 0% false-positive rate (0/20 known-clean fixtures) — full methodology in the project README.
