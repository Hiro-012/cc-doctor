A committed .env file with a plainly-named password in it produces zero findings from cc-doctor

By HiroCheck · Published 2026-09-13

Previous coverage on this blog has documented cc-doctor's secret detection missing specific provider token shapes (Stripe, GitLab, npm). This one is different in kind: it doesn't depend on which provider issued the secret, or what the token looks like. It's a gap in the one mechanism that exists specifically to catch everything the named patterns don't — and it's triggered by the single most common way a secret gets committed: an unquoted line in a .env file.

The generic fallback's actual requirement

secrets-scan.js backstops its five named patterns (AWS, GitHub, Anthropic/OpenAI-style, Slack, PEM blocks) with a catch-all that's supposed to be format-agnostic — it flags any sufficiently long value assigned to a credential-shaped key, regardless of what the value looks like:

const GENERIC_SECRET_PATTERN =
  /(?:api[_-]?key|secret|password|token)\s*[:=]\s*['"]([^\s'"]{20,})['"]/gi;

Read closely, the value isn't just "20+ characters" — it has to sit between a pair of quote characters, ['"]...['"]. That's a reasonable way to delimit a JSON or YAML string value. It also means the pattern cannot, by construction, ever match the standard shell/dotenv syntax used by Node's dotenv, Python's python-dotenv, Docker Compose's env_file, and every .env.example template in wide use — where an unquoted value is the idiomatic form:

DATABASE_PASSWORD=CorrectHorseBatteryStaple2024

No quotes appear anywhere in that line. The five named patterns don't require quotes (a raw AWS key or GitHub PAT matches wherever it appears), but they only cover five specific shapes. Once a secret's format isn't one of those five, the generic pattern is the only thing left to catch it — and dotenv syntax is exactly the one place that pattern's own quote requirement can never be satisfied.

Reproduced against the real CLI

A fresh git repo with a two-line .env committed, no quotes, both lines using a key name from the generic pattern's own list (password / token) with 20+ character values that aren't placeholders and aren't degenerate masks:

$ cat .env
DATABASE_PASSWORD=CorrectHorseBatteryStaple2024
STRIPE_SECRET_TOKEN=zzq7f3k9d2h5j8m1n4p6r0s2t5v7w9x1y3

$ git add .env && git commit -q -m init
$ npx cc-doctor .
[INFO] [info] claude-md: No CLAUDE.md found. Optional, but it lets Claude
Code pick up project-specific conventions automatically. (CLAUDE.md)

cc-doctor: 0 error(s), 0 warning(s), 1 info.
$ echo $?
0

Zero errors, zero warnings, exit code 0 — cc-doctor reports the repo clean. Both lines were deliberately built to survive every filter secrets-scan.js applies to a matched value: neither string matches the placeholder allowlist (your-*, <...>, changeme, example*, etc.), neither is a single-repeated-character mask, and neither contains the word "redacted" or "sanitized". These are exactly the two shapes the generic pattern exists to catch. It doesn't fire because the syntax, not the content, disqualifies the match.

Isolating quotes as the actual cause

Wrapping the same value in quotes — a form .env parsers also accept, just not the one most templates use — changes nothing about the secret and flips the result:

$ cat .env
DATABASE_PASSWORD="CorrectHorseBatteryStaple2024"

$ npx cc-doctor .
[ERROR] [error] secrets-scan: Possible Generic assigned secret committed
in .env. If real, rotate it immediately and remove it from git history. (.env)
[INFO]  [info]  claude-md: No CLAUDE.md found. ...

cc-doctor: 1 error(s), 0 warning(s), 1 info.
$ echo $?
1

Same key, same value, same file, same tool run seconds apart. The only difference between a silent pass and a flagged secret is two quote characters that dotenv syntax doesn't require and most real .env files in the wild don't include.

What cc-doctor checks

cc-doctor is a free CLI that scans a repo's git-tracked files for hardcoded secrets, plus Claude Code-specific misconfigurations: an unscoped Bash(*) permission grant, a committed settings.local.json, hooks pointing at scripts that no longer exist, and hardcoded credentials in .mcp.json. It runs entirely against the local filesystem and git index — no network access, no API key required.

npx cc-doctor            # scan the current directory
npx cc-doctor path/to/repo

Measured against cc-doctor's 49-fixture accuracy corpus, the tool's recall is 100% (29/29 known-bad fixtures) with a 0% false-positive rate (0/20 known-clean fixtures) — full methodology in the project README. The corpus's one existing .env-style fixture uses a value shaped like an Anthropic/OpenAI-style key (sk-...), which one of the five named patterns catches regardless of quoting — so it doesn't exercise the generic pattern's quote requirement, and this gap doesn't move either number. It's a coverage hole the corpus doesn't yet test for, not a regression. Nothing in this article changes cc-doctor's code; it documents the exact condition under which the generic check stays silent, with the reproduction steps above to verify it independently.
