cc-doctor's .mcp.json secret check never looks at args — the exact field Context7's own docs tell you to put your API key in

By HiroCheck · Published 2026-09-17

cc-doctor's mcp-config.js is supposed to catch a hardcoded credential inside .mcp.json. It inspects two places on each MCP server entry: env and headers. A committed .mcp.json can carry a credential in a third place — the args array, which is how a real, currently-documented MCP server (Upstash's Context7) tells you to configure its API key. That field is never read by this check at all, in any form.

What the check actually iterates over

From lib/checks/mcp-config.js, the whole function body:

const servers = config.mcpServers ?? {};
for (const [name, server] of Object.entries(servers)) {
  const env = server.env ?? {};
  for (const [key, value] of Object.entries(env)) {
    if (looksLikeHardcodedSecret(value)) { /* report.error(...) */ }
  }

  const headers = server.headers ?? {};
  for (const [key, value] of Object.entries(headers)) {
    if (looksLikeHardcodedSecret(stripAuthScheme(value))) { /* report.error(...) */ }
  }
}

Two loops, two fields: server.env and server.headers. server.args is never referenced anywhere in the file — not read, not iterated, not passed to looksLikeHardcodedSecret under any name.

Args is not a hypothetical place to put a secret

Upstash's own Context7 MCP quickstart gives this exact install command and config shape for authenticating with an API key:

claude mcp add --scope user context7 -- npx -y @upstash/context7-mcp --api-key YOUR_API_KEY

{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp", "--api-key", "YOUR_API_KEY"]
    }
  }
}

That's not a contributor's mistake — it's the vendor's documented configuration. A developer who follows it literally, then commits their working .mcp.json with the placeholder replaced by their real key, has put a credential exactly where mcp-config.js never looks.

Case 1: isolating the gap with a format the check already recognizes

To confirm this is about location, not just value shape, the same GitHub-PAT-shaped value (a format looksLikeHardcodedSecret already recognizes) was placed in env in one fixture and in args in an otherwise-identical one:

// case-ghp-env/.mcp.json
{ "mcpServers": { "gh-server": {
    "command": "npx", "args": ["-y", "gh-mcp-server"],
    "env": { "GITHUB_TOKEN": "ghp_ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghij" }
}}}

// case-ghp-args/.mcp.json
{ "mcpServers": { "gh-server": {
    "command": "npx",
    "args": ["-y", "gh-mcp-server", "--token", "ghp_ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghij"]
}}}

Running the unmodified CLI against each:

=== ghp_ token in env ===
[ERROR] [error] mcp-config: .mcp.json server "gh-server" has what looks like a hardcoded secret
  in env.GITHUB_TOKEN. Use an env var reference (e.g. "${GITHUB_TOKEN}") instead of committing
  the literal value. (.mcp.json)
[ERROR] [error] secrets-scan: Possible GitHub Personal Access Token committed in .mcp.json. ...
cc-doctor: 2 error(s), 0 warning(s), 1 info.
EXIT: 1

=== ghp_ token in args ===
[ERROR] [error] secrets-scan: Possible GitHub Personal Access Token committed in .mcp.json. ...
cc-doctor: 1 error(s), 0 warning(s), 1 info.
EXIT: 1

The mcp-config finding disappears the moment the exact same value moves from env to args — nothing else about the file changed. Only secrets-scan.js, the unrelated whole-file regex backstop that greps every git-tracked file's raw text regardless of JSON structure, still catches it here, because a GitHub PAT's shape happens to be on secrets-scan.js's five-pattern list too. That backstop is what keeps this particular case from being a full miss.

Case 2: the real Context7 key format has no backstop left

A Context7 API key looks like ctx7sk-<uuid> — a prefix followed by hyphen-delimited hex groups, e.g. ctx7sk-ff0c5d4d-0a4f-4565-8952-65ce0d547de7. Using the exact config shape from Context7's own quickstart, committed to git:

{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp", "--api-key",
                "ctx7sk-ff0c5d4d-0a4f-4565-8952-65ce0d547de7"]
    }
  }
}
$ node bin/cli.js case-args-context7
[INFO] [info] claude-md: No CLAUDE.md found. Optional, but it lets Claude Code pick up
  project-specific conventions automatically. (CLAUDE.md)

cc-doctor: 0 error(s), 0 warning(s), 1 info.
EXIT CODE: 0

Nothing. And moving the same value into env instead of args — the placement mcp-config.js does read — produces the identical zero-error result, confirmed by running the CLI against that fixture too. So this isn't only the args gap; the value's own shape independently defeats every mechanism that could have caught it, in either location. Checked directly against the three functions involved:

looksLikeHardcodedSecret("ctx7sk-ff0c5d4d-0a4f-4565-8952-65ce0d547de7")
  → false   // matches none of the four fixed prefixes (sk-, ghp_, AKIA, xox*)

SECRET_PATTERNS (secrets-scan.js), tested against the full committed file text:
  AWS Access Key ID              → false
  GitHub Personal Access Token   → false
  Anthropic/OpenAI-style sk-     → false   // "sk-" appears mid-string, but the regex needs
                                             // 20+ *contiguous* alphanumeric chars after it,
                                             // and the UUID-style body has a hyphen every
                                             // 8 characters, so no run is ever long enough
  Slack token                    → false
  Private key block              → false

GENERIC_SECRET_PATTERN, tested against the full committed file text:
  → no matches   // it requires key[:=]"value" syntax; "--api-key" and the key value
                   // are two separate quoted array elements with no ":" or "=" between them

Three independent mechanisms, three independent reasons, one real credential, zero findings: mcp-config.js doesn't read args at all (Case 1's gap); secrets-scan.js's named patterns don't match this shape even when they do get to see the text, because the hyphens inside the UUID-style body break the contiguous-run requirement the sk- pattern needs (a different mechanism from the wrong-prefix gap covered previously for Stripe/GitLab/npm keys — those failed on prefix shape, this fails on internal structure even where the prefix substring is present); and the generic fallback requires a JSON key-value pairing that a CLI flag followed by its value, as two positional array entries, never produces.

What cc-doctor checks

cc-doctor is a free CLI that scans a repo's git-tracked files for hardcoded secrets, plus Claude Code-specific misconfigurations: an unscoped Bash(*) permission grant, a committed settings.local.json, hooks pointing at scripts that no longer exist, and hardcoded credentials in .mcp.json. It runs entirely against the local filesystem and git index — no network access, no API key required.

npx cc-doctor            # scan the current directory
npx cc-doctor path/to/repo

Measured against cc-doctor's 49-fixture accuracy corpus (npm test / node --test test/accuracy.test.js, run unmodified for this article):

Full methodology in the project README. Neither test/accuracy.test.js nor test/scan.test.js contains a single fixture that uses an args field on an MCP server entry — the corpus was never built to exercise it, so this gap moves neither number; it's a coverage hole, not a regression. Nothing in this article changes cc-doctor's code — both reproductions above were run against the unmodified CLI (npm test: 60/60 passing).
