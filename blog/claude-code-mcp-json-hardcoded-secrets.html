Two Claude Code config mistakes that leak secrets or grant too much

By HiroCheck · Published 2026-08-07

Claude Code reads its behavior from a handful of files in a repo: .claude/settings.json, .mcp.json, and CLAUDE.md. They're plain JSON and Markdown, edited by hand, usually while focused on getting a feature working rather than on the file's security implications. Two mistakes show up often enough to be worth checking for specifically.

1. A hardcoded token in .mcp.json

A remote MCP server entry commonly needs an auth header:

{
  "mcpServers": {
    "internal-api": {
      "type": "http",
      "url": "https://api.internal.example.com/mcp",
      "headers": {
        "Authorization": "Bearer sk-live-abc123..."
      }
    }
  }
}

Written this way, the token is committed to git the moment .mcp.json is added — plainly, in plaintext, in the same history as the rest of the repo, discoverable by anyone with read access (or by anyone if the repo is public, or later made public). The fix is the same pattern used everywhere else config touches secrets: reference an environment variable instead of a literal value, and let the actual secret live in the environment or a local, gitignored file.

2. Bash(*) with no deny rules

.claude/settings.json can grant blanket shell access:

{
  "permissions": {
    "allow": ["Bash(*)"]
  }
}

This is the difference between Claude Code asking before running an unfamiliar command and running anything without asking — including commands that read .env files, call out to the network, or modify git history. It's rarely written this way on purpose; more often it's a leftover from quickly clearing a string of permission prompts during a long session, never narrowed back down afterward. A narrower allowlist, or an allowlist paired with explicit deny rules for the commands that matter, keeps the convenience without the blanket grant.

Checking for both automatically

cc-doctor is a free, offline CLI that scans a repo's Claude Code configuration for these two patterns and others: invalid JSON, hooks pointing at scripts that don't exist on disk, settings.local.json committed to git (it's meant to stay local, per Claude Code's own convention), and a git-tracked-file scan for common secret formats (AWS keys, GitHub tokens, Slack tokens, private key blocks, and generic api_key = "..."-style assignments).
